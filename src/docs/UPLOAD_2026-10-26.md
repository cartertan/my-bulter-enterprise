### Recommended route using the existing repository

Open Terminal in the existing My Bot Platform project folder. Keep its Git history; do not run `git init` or copy the source archive over it. The repository was checked on branch `main` with remote `https://github.com/cartertan/my-bulter-enterprise.git`. Confirm those values before continuing:

```zsh
git branch --show-current
git remote -v
git status --short
python3 -m pytest -q -p no:cacheprovider src/tests
node --check src/static/app.js
python3 scripts/package_release.py --check
git diff --check
```

If tests fail, stop and resolve them before publishing. Then stage only the reviewed files:

```zsh
git add -- scripts/package_release.py src/app.py src/providers.py src/requirements.txt \
  src/documents.py src/static/app.js src/static/index.html src/README.md \
  src/tests/test_app.py src/tests/test_scenarios.py src/tests/test_documents.py \
  src/docs/DOCUMENT_WORKFLOW.md src/docs/UPLOAD_2026-10-26.md \
  src/docs/GALLERY.md src/docs/screenshots/document-memory.jpg
git diff --cached --stat
git diff --cached --check
git status --short
```

Review the staged filenames. If unrelated files were already staged, unstage those specific files before committing. When the staged change is correct:

```zsh
git commit -m "feat: add document workflows and fix Bulter model management"
git fetch origin
git log --oneline HEAD..origin/main
```

If the last command lists commits, the remote contains work you do not yet have: stop and reconcile it before pushing. If it lists nothing and you are still on `main`, upload:

```zsh
git push origin main
```

If authentication is requested, use your normal GitHub authentication flow. Do not paste credentials into project files. If GitHub rejects the push, do not force-push. Review the reason and preserve remote history.
